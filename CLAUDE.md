# AutoDealer — нейроассистенты для автосалона «АвтоГрад»

Учебный проект. Дилер, модели, цены, вакансии, имена, телефоны и банки-партнёры вымышлены; реальные персональные данные не используются.

## Структура

| Путь | Что там |
|---|---|
| `ENGINEERING_JOURNAL.md` | Реестр принятых решений (ADR). Единственный источник правды по «что решили и почему» |
| `docs/pitch/` | Презентация проекта для заказчика — возвращаемся к ней в ходе разработки |
| `docs/plan/` | План реализации по этапам с критериями приёмки |
| `docs/architecture/` | Технические страницы: контуры, потоки ПДн, деградация |
| `docs/prompts/` | Системные промпты трёх ассистентов |
| `docs/knowledge-base/` | FAQ, типовые обращения, скрипты по ролям |

## Рабочие правила

**Журнал решений ведётся автоматически.** Как только решение подтверждено в диалоге (выбор платформы, сервиса, схемы данных, формата промпта) — оно дописывается в `ENGINEERING_JOURNAL.md` новой записью `ADR-NNNN` без отдельной просьбы. Формат записи: дата, статус, контекст, решение, следствия, ссылка на артефакт. Принятые записи не переписываются: при смене курса заводится новая со статусом «заменяет ADR-NNNN».

**Страницы проекта — один визуальный набор.** Питч и технические страницы используют общую палитру и типографику (petrol `#0E5257`, бумага `#F1F2EE`, Unbounded / Golos Text / IBM Plex Mono). Новая страница наследует эти токены, а не изобретает свои.

**Решения из журнала обязательны к соблюдению.** Прежде чем предлагать архитектурное решение, сверься с `ENGINEERING_JOURNAL.md` — в частности с ADR-0002 (граница Python / n8n и запрет ПДн в n8n).
